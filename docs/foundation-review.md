## 怎样查看

运行 `npm run dev`，打开 `/examples/foundation-study.html`。每组依次是基线、单一变量、组合观察。切换直线、弧线和急转折线；三种路径各有九格，共27个样片。锋尖叠层用红线表示笔路，绿虚线表示接触区中心。

中段按笔、用锋转换位置和笔尾枯润可以分别调整。同一笔保留各自的控制通道，按生成笔路的弧长过渡。两笔组合另外保留独立输入、种子和时间。JSON保存编辑源和编译结果，载入时检查版本及重新生成结果；接口见[可编辑笔法文档](foundation-brush.md)。

## 样片观察

- 提按能够改变同一笔中的接触宽度，输入零压力继续离纸。原始路径仍可编辑；基线原本也有作者设置的起收压力，不能把其尖收全部归功于新控制。
- 中侧用锋通过锋尖与接触区的偏移、展开和转向表现，叠层能检验这种关系；尚未还原真实笔毫翻转、调锋或不同纸面的受力。
- 润段增加连续实墨，减少此前整笔灰色线束的表现；枯段保持较深墨色并增加顺势断白，没有靠整笔变淡表示枯笔。干段仍可见程序线束感，尚不能认定达到自然散毫质感。
- 急转处采用有限接触范围内的方向过渡，减少接触法线骤变造成的切角；锋尖的原始折线仍保留。这是接触近似，不能当作真实转笔动作已成立。
- 两笔叠加用于观察组合及独立编辑，不作为积墨法成立或先后次序艺术效果的证据。

## 工程验证

`npm test` 的59项测试和 `npm run check` 通过。覆盖纯Node生成、数据所有权、版本拒绝、局部编辑、稀疏通道、控制锚点、零压力与接触边界，以及渲染状态保护。已有接口和旧场景继续经过原有测试。

真实浏览器检查了三种笔路、27个样片：语义重新编译与保存结果一致；同版本同后端JSON重放和乱序定位后像素一致；局部压力编辑保持其他通道及作者路径；种子变化、组合显露与露纸观察均符合检查条件。检查仅证明这些工程行为，不给艺术评分，也不覆盖整幅山水的性能。

交互检查包括三个滑杆、笔路选择、锋尖叠层、整批11笔JSON载入，以及拒绝未知生成器和源／结果不一致的文档。导出按钮已在浏览器触发；临时文件、截图及日志保存于仓库外。缓存为不可变笔迹的沉积几何计划，仍需逐帧向Canvas提交路径，并非位图图集缓存。

生成器版本标识动作编译语义，结果不含冻结的渲染纹理。跨升级精确重放还需固定库／渲染器版本、浏览器后端、尺寸及渲染选项；只核对编译数据不能证明未来材质升级后像素不变。
