# 笔墨山水技法库需求

2026-11-19，根据已确认的讨论整理。代码仓库：[zmhhaha/ink-landscape](https://github.com/zmhhaha/ink-landscape)。

OpenSpec 权威记录位于现有 armbianbegin 项目 `ec663f5a-53d3-4a0e-9037-933eb788d183`，独立变更 `add-ink-landscape-technique-library`，能力规格 `ink-landscape-techniques`。本文件是便于代码开发查阅的需求摘要；不在公开代码仓库复制私有 OpenSpec 存储或鉴权信息。

## 目标

建设一个可独立复用的 JavaScript／TypeScript 笔墨山水技法函数库，让创作 Agent 调用经过打磨的笔墨工具，自主组织路径、造形、构图与运动。库可用于图片学习、视频制作及以后的其他项目；首版以 Canvas 2D 为实现基础。

原型已有的 `pima`／`axe` 等名称表示程序近似。函数存在、测试通过或成功出图，都不等于笔法、皴法和整幅画面的艺术效果已验收。

## 架构与边界

| 层级 | 职责 | 技术安排 |
| --- | --- | --- |
| 几何与笔势 | 路径、提按、笔锋方向、区域、山体结构及方向场 | 纯 TypeScript；不依赖 DOM 或渲染器 |
| 基础笔墨 | 勾线、圆锋／侧锋、枯润、飞白、点苔、铺染 | Canvas 2D 首版 |
| 技法组合 | 披麻皴、斧劈皴、积墨，以及服务造形的用笔组织 | 组合可检查、可修改的基础笔触 |
| 材质与合成 | 纸纹、局部洇化、墨色沉积、云雾融合 | Canvas 基线；Shader 为独立可选研究 |

调用者可以自定路径、区域、方向场与组合方式。完整山水、山石、松树等高层配方可以作为示例，但不能成为唯一创作入口或固定构图模板。

笔触与场景应可序列化、检查、保存并重建修改。当前 builder 冻结返回数据，TypeScript 调用者通过对象展开与 `map` 创建修改版本；JavaScript 也可克隆后修改。方向场回调只在生成阶段运行，实际笔触保存在场景中。

库提供执行工具；WikiSkill 解释技法如何选择、组合、评价与调整；Agent 负责作品创作；HyperFrames 后续驱动作品的绝对时间与输出。库本身不要求部署成公共网络服务。

## 首版技法目标

1. 基础用笔：提按勾线、圆锋／侧锋变化、短笔与点苔、枯笔断白。分别提供局部样片，说明路径、压力、方向、墨色与枯润参数的可观察作用。
2. 墨法：淡墨铺染与逐层加墨，控制浓淡和干湿的视觉差异。多遍透明填色只算工程原型，积墨的方法和效果需单独打磨。
3. 皴擦：先研究受披麻皴、斧劈皴启发的两组技法。笔触顺岩面走势，保留疏密、粗细和断续，支持不同区域与方向场。
4. 空间与留白：在完整组合中形成近浓远淡、体块主次、云根和空白。支持调用者设计遮罩／区域与合成关系，不预设所有云雾必须同一种擦除方法。

重点排查的失败表现包括硬边多边形／剪纸感、均匀平行刷丝、挂帘状长纹、孤立随机短线、重复章印，以及把云雾画成等强白横带。增加笔数或统一模糊不能代替造形与笔势。

## 每项技法的验收方式

1. 明确要学习的局部效果及可观察标准，保存实际可访问的参考与观察范围。
2. 保留绘制源码、输入路径／区域、参数、种子、库版本及实际输出；同题对照时固定尺寸、后端及相关条件，说明改变的变量。
3. 查看局部与整体画面，记录改善、退步和仍未解决的问题。运行成功、像素发生变化和画面质量提升分别记录。
4. 换一组轮廓、笔势或布局验证一次，检验能否迁移；再检查完整山水组合。只适用于原例的配方标明其局限。
5. 技术验证、参考相似度／技法表现、对比改善、迁移结果和开发者认可分别保存。实验可在预算内继续迭代，不套用正片用户的一轮加两轮规则。

参考像素可以用于观察和比对，公共库的运行不依赖某个原视频网址或私有截图。对参考学到的方法应整理成独立说明；公开示例仅包含原创或许可明确的内容。

## 时间与资源

固定场景、种子、画布尺寸、库版本与后端下，默认清空重绘应支持绝对时间乱序定位和重复生成。`clear: false` 是有意叠加，结果依赖已有像素；不纳入调用次序独立性的承诺。

先验证单帧画面，再验证连续运动。当前 stroke 时间参数表示路径显露、wash 时间参数表示浓度渐入；不据此认定自然落笔、墨色扩散或动画艺术效果达标。跨浏览器／后端不承诺逐像素相等。

性能记录应绑定分辨率、实际运行环境、耗时与资源观察范围。无 GPU 时不假定 Shader 更快，不把笔触总数或上下文限制解释成通用性能上限。

## Shader 的采用条件

针对明确问题逐项研究，例如湿墨边缘、局部纸纹或云雾融合。保持同一 Canvas 源画面及输入，对 Shader 开关进行对照；分别记录画面收益、退步和开销，保留纯 Canvas 基础路径。

尚未证明收益的 Shader 不成为首版笔墨库的完成前提。噪声扰动、模糊与混合只能称视觉模拟；未经物理模型和验证，不称真实纸纤维、毛细扩散或流体模拟。

## 知识与消费

有效技法可整理为 WikiSkill 方法包，说明适用目标、步骤、参数关系、失败反例、调整方式及静态／动态验证范围，并关联适用的库版本或 commit。库升级后应检查方法是否仍适用。

发布继续沿用效果／学习库的人工决定规则：由开发者发起整库快照，经自动化整理生成 WikiSkill；浏览和回退对应生成的 WikiSkill，保留最近五个整库版本。新增代码或样例不自动触发知识发布。

图片学习库、正式视频 Agent 和 HyperFrames 的消费需分别留实际执行证据。独立预览页成功不等于已经接入生产。后续游戏等项目可以复用相同包，首版不以额外服务上线为前提。

## 已有基础与后续任务

后续技法扩展沿用 `add-ink-landscape-technique-library`。先在《枯木寒鸦图》的叉口和洞口验证枝干勾皴与木结，再检验控笔、线皴和点皴的改进，扩展丝毛、水面线组、勾花点叶与撞粉。方案及样片验收见 [笔法改进与扩展设计](technique-development-design.md)。

现状基线：`d56779285588d88479e4282762e5de00ae0d271a`。

- 已有工程基础：独立 GitHub 仓库与 MIT 许可、纯 TypeScript 场景核心、Canvas 笔触／铺染／两种皴擦原型、四类参数示例、16 项测试以及四组真实浏览器像素检查。
- 优先待办：基础笔法局部打磨，点苔／积墨／云雾留白的可复用方法，两种皴法的参考对照与换形验证，完整画面组合验收。
- 后续待办：技法 WikiSkill 与版本关联、现有学习库和正式制作实际消费、连续运动验证。
- 可选研究：Shader 材质合成及其可确认的质量／资源收益。

既有视频服务的水墨单帧艺术目标、正式 Mali 准入、连续运动及生产调度任务保留原状态；本库的原型和工程测试不替它们验收。

## 2026-11-24 库消费与发布前检查

多个文档组合时，以调用者指定的命名空间区分实例，保留局部默认 ID、笔迹种子、坐标、时序和配方；同一内容允许多次使用。组合返回独立、冻结的普通场景，不隐式转换墨水事件。

保留根入口兼容，同时提供核心、Canvas、笔法、皴法、墨水、造形和学习资料的子入口。核心与 Canvas 的实际模块加载不得连带研究语料。区域生成和显式皴笔共享稳定的技法 ID，分别声明实际能力，不以改名代替实现。

渲染缓存只复用完整不可变输入；可变 JSON、浅冻结后的子对象编辑及绝对时间乱序定位继续有效。非法 CSS 墨色和纸色使用显式兜底，绘制后恢复调用方状态。

打包前构建，并从无 `dist/` 的源码副本实际打包、安装和验证全部公开入口及类型。CI 检查 Node 20/22、生成资料一致性与真实 Chromium 渲染；`private: true` 继续控制 npm 发布。实现与验证范围见 [本轮 review 说明](library-readiness.md)。
